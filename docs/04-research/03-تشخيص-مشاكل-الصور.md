## المشكلة 1: صورة الواتساب "ملونة غريبة ولا تدل على شيء"

### شكوى المالك (حرفياً)
> «عندما ترسل الرابط عبر الواتساب مثلاً، رابط الصفحة، تظهر الصورة حق الرابط مش صورة الموقع، تظهر صورة ملونة غريبة، يعني ولا تدل على أي شيء»

### التشخيص — 3 خطوات فحص

**الخطوة 1: هل الوسوم موجودة؟** ✅ نعم، كاملة وصحيحة
```
og:image        = https://asoulaldiafa.com/og-image.jpg
og:image:width  = 1200
og:image:height = 630
og:image:alt    = أصول الضيافة - خدمات الضيافة الفاخرة
twitter:card    = summary_large_image
```
إذاً المشكلة **ليست** في الوسوم.

**الخطوة 2: هل الملف موجود؟** ✅ نعم
```
HTTP 200 · content-type: image/jpeg · 13,469 بايت
```

**الخطوة 3: ما محتوى الملف فعلاً؟** 🔴 **هنا العطل**

```
$ file og_old.jpg
og_old.jpg: PNG image data, 1200 x 630, 8-bit/color RGB
```

**عطلان في ملف واحد:**

| # | العطل | التفصيل |
|---|---|---|
| **أ** | **تعارض الصيغة** | الملف اسمه `.jpg` والسيرفر يعلنه `image/jpeg`، لكن محتواه الفعلي **PNG**. بعض المعالجات (واتساب/تلغرام/بعض الكواشط) ترفض الصورة أو تفشل في فكّها عند تعارض الترويسة مع المحتوى. وجوجل توصي صريحاً: *"It's also a good idea to have the extension of your filename match with the file type"* |
| **ب** | **الصورة فارغة فعلاً** | 13 كيلوبايت لصورة 1200×630 = مؤشر على صورة بلا تفاصيل. الفحص البصري أكّد: **تدرّج بني/أسود فقط. لا شعار، لا نص، لا صورة، لا اسم**. هذا حرفياً وصف المالك: "صورة ملونة غريبة ولا تدل على أي شيء" |

### حالة الموقع الجديد ✅
```
public/og-image.jpg → JPEG image data, 1200x630, progressive · 55,152 بايت
```
- الصيغة **مطابقة** للامتداد ✅
- المحتوى: بطاقة كاملة فيها «أصول الضيافة» + «قهوجيين وصبابين قهوة وضيافة مناسبات» + «جدة · ينبع · مكة المكرمة · المدينة المنورة · بدر» + `asoulaldiafa.com` ✅

**الخلاصة:** المشكلة **محلولة أصلاً في الجديد**. مجرد استبدال النشر يُصلحها.

### ⚠️ تحسين مطلوب في الجديد (من توثيق جوجل)
جوجل تقول في `google-images`:
> "Avoid using a generic image (for example, your site logo) or **an image with text** in the schema.org markup or `og:image` meta tag."

بطاقة الجديد **نصية بالكامل** — أفضل من الفراغ بكثير، لكن الأمثل: **صورة فعلية لفريق الصبّابين أثناء العمل** + لمسة هوية. ينتظر صور المالك الجديدة.

## المشكلة 2: المنافسون يظهرون بعدة صور في جوجل، وأنا بصورة واحدة

### شكوى المالك (حرفياً)
> «ابحث مثلاً قهوجيين في ينبع… بعضهم يظهروا وتحته عدة صور، وأنا أظهر بس، وجوه لو صورة واحدة، ليش؟ أيش السبب؟»

### التشخيص — 4 أسباب مثبتة

**الحقيقة الأولى:** الصورة الظاهرة في نتيجة البحث تُسمّى `text result image`، واختيارها **آلي بالكامل** عند جوجل. لكن التوثيق يحدد كيف تُؤثّر عليه.

#### السبب أ 🔴 — `image` في البيانات المهيكلة = **الشعار**

القديم:
```json
"image": "https://asoulaldiafa.com/logo.webp"
```
الجديد (`src/lib/schema.ts:67`):
```ts
image: `${SITE_URL}/logo.webp`,
```

**نص جوجل الصريح:**
> "**Avoid using a generic image (for example, your site logo)**"

نحن نقول لجوجل حرفياً: "أهم صورة في هذا الموقع هي الشعار". فتعرض الشعار وحده. **هذا هو السبب المباشر لظهور صورة واحدة "لا تدل على شيء"**.

#### السبب ب 🔴 — لا `primaryImageOfPage`

جوجل تعرض طريقتين للتأثير على اختيار الصورة:
1. `primaryImageOfPage` في schema.org
2. `og:image`

الموقع يستخدم `og:image` (وكان معطوباً)، و**لا يستخدم `primaryImageOfPage` إطلاقاً** (صفر نتائج في `src/lib/`).

#### السبب ج 🟠 — لا خريطة صور (Image Sitemap)

`src/app/sitemap.ts` موجود لكن **بلا** حقل `images`. جوجل:
> "You can provide the URL of images we might not have otherwise discovered by submitting an image sitemap"

الموقع فيه **97 صورة** في الصفحة الرئيسية وحدها، وكلها تعتمد على الاكتشاف التلقائي فقط.

#### السبب د 🟠 — كل الصور عبر `/_next/image?url=…`

```
src="/_next/image?url=%2Fimages%2Fsetups%2Fsetup-1.webp&w=1920&q=75"
```
هذا صالح تقنياً (جوجل تقرأ `src` من `<img>`)، لكن:
- أسماء الملفات مُرمَّزة (`%2F`) → جوجل: *"the filename can give Google very light clues about the subject matter"* — نفقد هذه الإشارة
- الأسماء نفسها عامة: `setup-1.webp` … `setup-7.webp` → جوجل: *"Avoid using generic filenames like `image1.jpg`, `pic.gif`"*
- الأمثل: `qahwajiin-jeddah-hafl-zawaj.webp` بدل `setup-1.webp`

#### تحقق إضافي: تكرار نص alt
`scripts/check-assets.mjs` يُحذّر أصلاً من **تكرار نص alt = "أصول الضيافة"**. جوجل تعتمد alt أساساً لفهم موضوع الصورة. alt مكرر عام = صور غير مفهومة لجوجل.

## معايير الصور الرسمية — مرجع سريع

المصدر: `developers.google.com/search/docs/appearance/google-images`

| القاعدة | النص |
|---|---|
| **استخدم `<img>`** | جوجل **لا تفهرس صور CSS** (`background-image`) |
| الصيغ المدعومة | BMP, GIF, JPEG, PNG, WebP, SVG, AVIF |
| مطابقة الامتداد | "a good idea to have the extension match the file type" ← **العطل في القديم** |
| `<picture>` | لازم `<img>` احتياطي بـ`src` |
| تجنّب | صورة عامة/شعار · **صورة فيها نص** · نسب أبعاد متطرفة |
| استخدم | دقة عالية · صورة تمثيلية للصفحة |
| أسماء الملفات | قصيرة ووصفية · تجنّب `image1.jpg` |
| alt | مفيد وغني بالمعلومة · **لا حشو كلمات** (= سبام) |
| السياق | ضع الصور قرب نص ذي صلة |
| ميزانية الزحف | نفس الصورة = نفس الرابط دائماً (للكاش) |
| نتائج غنية | حقل `image` **إلزامي** لأهلية الشارة في Google Images |
