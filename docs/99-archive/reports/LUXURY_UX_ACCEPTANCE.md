# مواصفة قبول تجربة الضيافة الفاخرة

تاريخ التحقق: 2026-08-11
المصادر الأصلية: Nielsen Norman Group، web.dev، W3C WCAG 2.2.

## المبدأ الحاكم

الفخامة الرقمية ليست كثرة المؤثرات؛ هي **وضوح سريع + دليل حقيقي + مسار حجز سهل + استجابة هادئة ومستقرة ومتاحة**.

## 1. Hero يشرح العرض قبل الزينة

- تجيب الشاشة الأولى فورًا: ما الخدمة، أين، ما الوعد القابل للإثبات، وما الخطوة التالية.
- النص المرجعي للعلامة يستخدم **«قهوجيين وصبابين» بالياء دائمًا**.
- H1 مرجعي: «قهوجيين وصبابين في جدة، ضيافة تترك أثرها من أول فنجان».
- Sub مرجعي: «حضور مرتب، وتفاصيل ضيافة تُنسّق بما يليق بمناسبتك وضيوفك.»
- CTA رئيسي واحد: «تواصل لتفصيل مناسبتك» أو «احجز ضيافتك».
- صورة أصلية تمثل الخدمة مع قص مستقل للجوال؛ لا صورة مولدة أو مخزنية عامة.
- العنوان والزر ظاهران دون انتظار فيديو أو animation، ويظهر طرف القسم التالي.
- إن وُجد فيديو فهو ليس شرطًا لفهم العرض، وله poster وبديل ساكن وتحكم واضح.

المصدر: [NN/g — Homepage Design: 5 Fundamental Principles](https://www.nngroup.com/articles/homepage-design-principles/).

## 2. الثقة دليل قريب من الوعد

- يلي Hero دليل مختصر: أعمال حقيقية، خطوات التجهيز، ومناطق الخدمة الفعلية.
- كل رقم أو شهادة أو شعار جهة له مصدر وإذن؛ وإلا يُحذف.
- لا وعود تشغيلية غير مثبتة مثل التغطية الشاملة أو توقيتات مضمونة.
- نعرض أمثلة محددة: التجهيز، التقديم، تفاصيل الطاقم، ومخرجات المناسبة.
- نشرح ما يحدث بعد التواصل وما البيانات المطلوبة.

## 3. الجوال هو المسار الأساسي

- الترتيب: العرض ← الإثبات ← الخدمة ← العملية ← الأسئلة ← التواصل.
- لا hover أو swipe بوصفهما السبيل الوحيد؛ لكل وظيفة تحكم مرئي.
- الهاتف والبريد وواتساب روابط فعلية، والنموذج قصير بـlabels ظاهرة وأخطاء محددة.
- اختبار RTL، تكبير النص، لوحة المفاتيح، قارئ الشاشة، والوضعين الرأسي والأفقي.
- WCAG 2.2 يحدد `24×24 CSS px` حدًا أدنى لأهداف المؤشر وفق شروطه؛ الأزرار الأساسية تكون أريح من الحد الأدنى.

المصادر: [NN/g — Mobile UX](https://www.nngroup.com/articles/mobile-ux-study-guide/) و[W3C — Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum).

## 4. الأداء جزء من الفخامة

أهداف Google المنشورة عند الشريحة المئوية 75:

- `LCP ≤ 2.5s`
- `INP ≤ 200ms`
- `CLS ≤ 0.1`

أما أهداف المشروع الأشد (`LCP < 2s` و`CLS < 0.05`) فهي **أهداف داخلية طوعية**، ولا تُنسب إلى Google.

بوابات التنفيذ:

- صورة Hero قابلة للاكتشاف في HTML، ليست lazy، وأبعادها محددة.
- صور responsive بمقاسات فعلية، وتأجيل ما تحت الطية.
- تأجيل الفيديو والطرف الثالث، وتقليل JavaScript الأولي والمهام الطويلة.
- الأقسام الساكنة Server Components ما أمكن.
- أوزان خط محدودة وfallback قريب المقاييس.
- Lighthouse بوابة منع تراجع، لا بديلًا عن RUM وCrUX وPageSpeed Insights.

المصادر: [web.dev — Web Vitals](https://web.dev/articles/vitals) و[web.dev — Improve Core Web Vitals](https://web.dev/articles/top-cwv).

## 5. الحركة هادئة وهادفة

- الحركة تشرح حالة أو علاقة مكانية؛ لا scrolljacking أو parallax كبير أو نص ينتظر الحركة.
- تحريك `transform` و`opacity` عند الحاجة بدل خصائص layout/paint الثقيلة.
- `prefers-reduced-motion` يعمل في CSS وJavaScript مع نسخة ساكنة.
- المحتوى المتحرك تلقائيًا أكثر من خمس ثوان له وسيلة إيقاف/إخفاء؛ والأفضل ألا يبدأ فيديو Hero تلقائيًا.

المصادر: [web.dev — prefers-reduced-motion](https://web.dev/articles/prefers-reduced-motion) و[W3C — Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html).

## 6. الوصول بوابة قبول

- WCAG 2.2 AA، HTML دلالي، عناوين مرتبة، و`lang="ar" dir="rtl"`.
- alt وظيفي للمفيد و`alt=""` للزخرفي، وcaptions للفيديو ذي الصوت.
- كل الوظائف بلوحة المفاتيح مع focus واضح غير محجوب وإدارة صحيحة للحوارات.
- التباين: `4.5:1` للنص العادي و`3:1` للنص الكبير وفق WCAG.
- الحقول لها labels، والخطأ مرتبط بالحقل مع `aria-invalid` ورسالة حالة عند الحاجة.
- لا منع للتكبير؛ اختبار reflow وتباعد النص.

المصدر: [W3C — WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/).

## ترتيب التنفيذ

1. معنى Hero وCTA وصورة أصلية.
2. دليل حقيقي قريب من الوعد وحذف الادعاءات غير الموثقة.
3. مسار الحجز على الجوال ولوحة المفاتيح.
4. ميزانية الأداء الميدانية: Hero وJavaScript والخطوط أولًا.
5. حركة محدودة بعد اكتمال النسخة الساكنة.
6. WCAG 2.2 AA والاختبار اليدوي والأداء الميداني بوابات مستمرة.

## حدود المواصفة

- المبادئ عامة وموثقة، ومكيّفة لقطاع الضيافة؛ ليست تجربة تحويل خاصة بالمشروع.
- لا توجد نسبة زوار مثبتة في هذه المواصفة.
- لا تُعرض أرقام أو ادعاءات تسويقية دون مصدر وفترة قياس واضحة.
