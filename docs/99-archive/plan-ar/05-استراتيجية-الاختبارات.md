## 1. الهرم — ماذا نختبر وبأي كثافة

```
        ▲  E2E (Playwright)          ~15 سيناريو  — المسارات الحرجة فقط
       ╱ ╲ التكامل (Vitest+RTL)      ~30 اختبار   — المكوّنات التفاعلية
      ╱   ╲ الوحدة (Vitest)          ~80 اختبار   — كل منطق lib/
     ╱─────╲ الفحوص الآلية (scripts) ~10 فاحص     — سيو · أصول · تشابه · وصول
```

**فلسفتنا:** هذا موقع **تسويقي ستاتيكي**، لا تطبيق حالة معقد. لذلك ثقلنا الأكبر ليس في اختبار الوحدة التقليدي بل في **الفحوص الآلية للمحتوى والسيو والأصول** — لأن أخطر أعطال هذا المشروع (تشابه 97%، عناوين مكررة، ادّعاء «فرع»، صورة ضخمة) **لا يلتقطها اختبار وحدة إطلاقاً**.

## 2. البوابات الست — كل PR يمرّ بها إلزامياً

| # | البوابة | الأمر | يفشل عند |
|---|---|---|---|
| **G-1** | الأنواع | `npm run typecheck` | أي خطأ TS |
| **G-2** | الجودة | `npm run lint` | أي خطأ أو تحذير |
| **G-3** | الاختبارات | `npm run test -- --coverage` | فشل اختبار أو تغطية `lib/` < 80% |

## 3. اختبارات الوحدة (Vitest)

### 3.1 التغطية المطلوبة
| النطاق | الحد الأدنى |
|---|---|
| `src/lib/**` | **80%** خطوط · **80%** فروع |
| `src/components/ui/**` | **70%** |
| `src/app/**` | لا حد (يغطّيه E2E) |
| **تراجع التغطية** | ❌ ممنوع — أي PR يخفضها يفشل |

### 3.2 ما يجب اختباره حتماً في `lib/`

| الملف | الاختبارات المطلوبة |
|---|---|
| `schema.ts` | ✅ 4 موجودة → **وسّعها**: `ProfessionalService` صحيح · **لا يحتوي `address`** · `serviceArea` فيها كل المدن · كل مخرَج يمرّ `JSON.parse` · **صفر `LocalBusiness`** · **صفر `BRANCHES`** |
| `localPages.ts` | `localSlug()` يولّد slug صحيحاً · لا تكرار في `LOCAL_PAGES` · كل مدينة لها `ar` |
| `localContent.tsx` → `lib/content/*` | كل مدينة تُرجع `metaTitle` ≤ 60 · `metaDescription` 120–158 · `h1` غير فارغ · **≥ 5 أسئلة مختلفة نصياً بين المدن** |
| `serviceHubs.ts` | 5 مراكز · slug فريد · لا تكرار عناوين |
| `constants.ts` | صيغة الواتساب صحيحة · `SITE_URL` بلا `/` أخير |
| `utils/**` | كل دالة نقية |

### 3.3 نمط الاختبار المعتمد
```ts
// AAA: Arrange → Act → Assert. اسم الاختبار يصف السلوك لا التنفيذ.
describe("generateProfessionalServiceSchema", () => {
  it("لا يُصدر خاصية address لأن النشاط مزوّد خدمة بلا مقر", () => {
    const schema = generateProfessionalServiceSchema();
    expect(schema).not.toHaveProperty("address");
    expect(schema["@type"]).toBe("ProfessionalService");
  });

  it("يغطّي كل مدن الخدمة عبر serviceArea", () => {
    const schema = generateProfessionalServiceSchema();
    const names = schema.serviceArea.map((a) => a.name);
    expect(names).toEqual(expect.arrayContaining(["جدة", "ينبع", "بدر", "المدينة المنورة", "مكة المكرمة"]));
  });
});
```

**ممنوع:** اختبار يقرأ التنفيذ حرفياً (`toMatchSnapshot` لكائنات كبيرة)، اختبار بلا تأكيد، اختبار `it.skip` مدموج.

## 5. G-5 — فاحص السيو والمحتوى (الأهم في هذا المشروع)

**`scripts/seo-guard.mjs`** — يكتبه D9 في الموجة 0. يعمل على مخرَج `next build` (HTML الستاتيكي في `.next/server/app/`).

| # | الفحص | يفشل عند |
|---|---|---|
| **S1** | طول `<title>` | > 60 حرفاً أو < 30 |
| **S2** | تكرار العلامة | ظهور «أصول الضيافة» مرتين في نفس العنوان |

**مخرجات الفاحص:** جدول في سجل CI + تعليق تلقائي على الـ PR.

## 6. فاحص التشابه — قلب الخطة كلها

**`scripts/similarity-check.mjs`** — يُنفّذ داخل G-5. هذا الفاحص هو ما يمنع عودة المشروع إلى مأزق Doorway.

### 6.1 الخوارزمية المعتمدة (نفس منهجية التدقيق ليكون الرقم قابلاً للمقارنة)
1. استخرج **النص المرئي فقط** من HTML الصفحة (بلا وسوم ولا سكربتات ولا JSON-LD).
2. **حيِّد المتغيّرات:** استبدل كل اسم مدينة ومشتقاته بالرمز `__CITY__` (جدة/بجدة/في جدة/ينبع/بدر/المدينة المنورة/مكة المكرمة).
3. طبّع المسافات وعلامات الترقيم العربية.
4. احسب `SequenceMatcher.ratio()` لكل زوج صفحات من نفس العائلة.

### 6.2 العتبات الملزمة

| العلاقة | الحد الأقصى | القياس اليوم |
|---|---|---|
| مدينتان · نفس الخدمة | **60%** | 🔴 **97.37%** (`sababin-qahwa`) · **97.00%** (`diyafa-munasabat`) |
| مركز خدمة ↔ مركز خدمة | 60% | ✅ 43.43% |
| نفس المدينة · خدمتان | 60% | ✅ 33.63% |
| **كتلة الأسئلة الشائعة** | **40%** | 🔴 **100.00%** — متطابقة تماماً |
| صفحة جديدة ↔ أي صفحة قائمة | **60%** | — |

### 6.3 مقياس مساند إلزامي: الكلمات الحصرية
| المؤشر | اليوم | الحد الأدنى |
|---|---|---|
| كلمات موجودة في صفحة مدينة **دون غيرها** | **3.0%–4.7%** (14–22 من ~465) | **≥ 25%** |

> **معنى الرقم:** صفحة مدينة اليوم تحوي 3–4.7% محتوى خاصاً بها. **95%+ منها قالب مُعاد.** الهدف قلب المعادلة إلى ربع الصفحة على الأقل محتوى لا يصلح لمدينة أخرى.

### 6.4 اختبار القبول البشري — يُطبَّق في المراجعة
> **بدّل اسم المدينة في الصفحة. إن بقي كل ما فيها صحيحاً — الصفحة Doorway. ارفض الـ PR.**

الفاحص الآلي يمسك القالب. **العين البشرية تمسك الفراغ.** كلاهما إلزامي.

## 8. اختبارات الوصول (axe-core)

```ts
import AxeBuilder from "@axe-core/playwright";

test("لا خروقات وصول حرجة", async ({ page }) => {
  await page.goto("/");
  const results = await new AxeBuilder({ page })
    .withTags(["wcag2a", "wcag2aa", "wcag21aa"])
    .analyze();
  expect(results.violations.filter((v) => v.impact === "critical" || v.impact === "serious")).toEqual([]);
});
```

| البند | الحد |
|---|---|
| خروقات `critical` | **0** |
| خروقات `serious` | **0** |
| خروقات `moderate` | ≤ 3 موثّقة |
| النطاق | كل قوالب الصفحات (رئيسية · مركز · مدينة · تواصل · معرض) |

## 9. ملف CI — `.github/workflows/ci.yml`

```yaml
name: CI
on:
  pull_request: { branches: [main] }
  push:        { branches: [main] }

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - name: G-1 الأنواع
        run: npm run typecheck
      - name: G-2 الجودة
        run: npm run lint
      - name: G-3 الاختبارات
        run: npm run test -- --coverage
      - name: G-4 البناء
        run: npm run build
      - name: G-4b ميزانية الأصول
        run: node scripts/check-assets.mjs
      - name: G-5 السيو والتشابه
        run: node scripts/seo-guard.mjs

  e2e:
    needs: quality
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps chromium webkit
      - run: npm run build
      - name: G-6 E2E + الوصول
        run: npx playwright test
      - name: G-6b Lighthouse
        run: npx lhci autorun
      - uses: actions/upload-artifact@v4
        if: failure()
        with: { name: playwright-report, path: playwright-report/ }
```

**حماية الفرع `main` (يضبطها القائد الفني):**
- ✅ يتطلب مرور `quality` و`e2e`
- ✅ يتطلب مراجعة معتمدة واحدة على الأقل
- ✅ يتطلب فرعاً محدَّثاً قبل الدمج
- ❌ **ممنوع push مباشر** (R6) · ❌ ممنوع force push

## 10. سكربتات `package.json` المطلوبة

```jsonc
{
  "typecheck":  "tsc --noEmit",
  "lint":       "next lint --max-warnings=0",
  "test":       "vitest run",
  "test:watch": "vitest",
  "test:e2e":   "playwright test",
  "test:a11y":  "playwright test --grep @a11y",
  "check:seo":     "node scripts/seo-guard.mjs",
  "check:assets":  "node scripts/check-assets.mjs",

}
```

> **قبل أي PR:** شغّل `npm run check:all` محلياً. من يرسل PR أحمر يعطّل فريقاً من عشرة.
