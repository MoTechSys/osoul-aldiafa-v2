# 10 — بروتوكول العمل والدمج

**عشرة مطورين على مستودع واحد بلا بروتوكول = فوضى خلال أسبوع.**
هذا الملف يمنع التعارضات قبل حدوثها. اقرأه قبل أول `git checkout`.

---

## 1. الفرع والدمج

| البند | القاعدة |
|---|---|
| الفرع الرئيسي | **`main` فقط** — لا `develop` ولا `staging` |
| النشر | Vercel ينشر تلقائياً من `main` |
| المعاينة | Vercel Preview لكل PR — **راجعها قبل الموافقة** |
| **push مباشر على `main`** | ❌ **ممنوع منعاً باتاً (R6)** — الفرع محمي |
| force push | ❌ ممنوع نهائياً |
| عمر الفرع | **≤ 3 أيام** — الفرع الطويل يعني تعارضاً مؤلماً |
| حجم الـ PR | **≤ 400 سطر تغيير** — الأكبر يُقسَّم |
| الدمج | **Squash merge** فقط — تاريخ نظيف |
| بعد الدمج | احذف الفرع فوراً |

### 1.1 تسمية الفروع
```
{النوع}/{المطوّر}-{وصف-قصير}

```

**الأنواع:** `feat` · `fix` · `refactor` · `perf` · `content` · `chore` · `test` · `docs`


| # | القاعدة |
|---|---|

## 4. وصف الـ PR — القالب الإلزامي

```markdown
## ماذا
[جملة واحدة]

## لماذا
[المشكلة المُحلّة + مرجعها في 01-التدقيق أو 02-الخطة]
مثال: يعالج C3 (تكرار العلامة في 15/21 صفحة)

## كيف
[قرارات تقنية تستحق الشرح]

## الأثر المقيس
- حجم JS: قبل __ KB → بعد __ KB
- حجم public/: قبل __ → بعد __
- التشابه: قبل __% → بعد __%
- Lighthouse: Perf __ · A11y __ · SEO __

## لقطات (لأي تغيير بصري)
| قبل | بعد |
|---|---|
| | |
جوال 375px + سطح مكتب 1280px

## قائمة التحقق
- [ ] npm run check:all يمرّ محلياً
- [ ] لم أعدّل ملفاً خارج ملكيتي (§2)
- [ ] لم أضف تبعية بلا موافقة
- [ ] الخطوط الحمراء R1–R10 محترمة
- [ ] لا كلمة «فرع» · لا رقم غير موثّق
- [ ] كل صورة جديدة ≤ 100 KB · alt فريد
- [ ] فاحص التشابه < 60%
- [ ] راجعت معاينة Vercel على الجوال
```

## 5. المراجعة

| البند | القاعدة |
|---|---|
| الحد الأدنى | **مراجع واحد معتمد** |
| PR عالي الخطورة | **مراجعان** (§2.1) |
| زمن الاستجابة | **≤ 4 ساعات عمل** — الـ PR الراكد يعطّل فريقاً |
| المراجع | ليس كاتب الشيفرة أبداً |
| CI أحمر | ❌ لا يُراجَع أصلاً — أصلحه أولاً |

### 5.1 ما يفحصه المراجع
```
□ هل يحل المشكلة المذكورة فعلاً؟
□ هل بقي داخل حدود ملكيته؟
□ هل يخالف أي خط أحمر R1–R10؟
□ للمحتوى: هل تجتاز الصفحة اختبار «بدّل اسم المدينة»؟
□ هل الأرقام موثّقة؟ (R9)
□ هل أضاف "use client" بلا تعليق // السبب:؟
□ هل زاد JS أو وزن الصفحة بلا تبرير؟
□ هل الاختبارات تغطي الجديد؟
□ هل تعمل معاينة Vercel على الجوال؟
```

### 5.2 آداب المراجعة
- **اقترح، لا تأمر:** «ما رأيك لو…» بدل «غيّر هذا»
- **ميّز الإلزامي من الاختياري:** `[إلزامي]` مقابل `[اقتراح]`
- **امدح الجيد** — نراجع الشيفرة لا الشخص
- **عند الخلاف:** القائد الفني يحسم خلال ساعتين. **لا يُترك PR معلّقاً على جدال.**

## 6. اليوم العملي

| الوقت | النشاط |
|---|---|
| البداية | `git pull origin main` · اقرأ بطاقتك · حدّث حالتك |
| **وقوف يومي 10 دقائق** | أمس / اليوم / ما يعطّلني |
| أثناء العمل | commits صغيرة متكررة · شغّل `npm run check:all` قبل الدفع |
| النهاية | ادفع فرعك (لا تترك عملاً محلياً) · حدّث حالة الـ PR |
| **جمعة القياس** | D10 يعرض التقرير الأسبوعي على الفريق |

### 6.1 الإبلاغ عن حاجب
```
🚧 حاجب — {اسم المطوّر}
ما أحاول عمله: …
ما يمنعني: …
من يستطيع رفعه: …
منذ متى: …
```
> **قاعدة:** حاجب عمره > **4 ساعات** يُرفع إلى القائد الفني فوراً. لا تصمت يوماً كاملاً.

## 7. التعامل مع التعارضات

**الوقاية:** `git pull --rebase origin main` **يومياً على الأقل**. لا تنتظر ثلاثة أيام.

```bash
git checkout main && git pull origin main
git checkout fix/d1-titles
git rebase main
# عند تعارض: أصلح، ثم:
git add . && git rebase --continue
npm run check:all   # إلزامي بعد أي rebase
git push --force-with-lease   # ✅ مسموح على فرعك أنت فقط
```

> `--force-with-lease` مسموح **على فرعك الخاص**. ❌ **ممنوع مطلقاً على `main`.**
> **تعارض في ملف لا تملكه؟** توقّف. كلّم مالكه. لا تحسم بمفردك.

## 8. النشر والتراجع

### 8.1 النشر
Vercel ينشر تلقائياً من `main` بعد نجاح CI. **لا نشر يدوي.**

### 8.2 ما بعد النشر (خلال 15 دقيقة)
```bash
curl -sI https://asoulaldiafa.com/ | head -20   # 200 · br · x-vercel-cache
curl -s -o /dev/null -w "%{time_starttransfer}\n" https://asoulaldiafa.com/   # ≤ 0.2s (المرجع 0.047)
curl -s https://asoulaldiafa.com/sitemap.xml | head
```
+ افتح 3 صفحات على جوال حقيقي · تحقّق من وصول أحداث GA4.

### 8.3 التراجع
| الحالة | الإجراء | المدة |
|---|---|---|
| عطل حرج (صفحة بيضاء · 500 · انهيار تحويل) | **Instant Rollback في Vercel** | < 5 دقائق |
| عطل متوسط | `git revert` + PR سريع | < ساعة |
| عطل سيو (صفحة بلا فهرسة) | لا تتراجع فوراً — راقب 7 أيام | — |

**من يقرر التراجع:** القائد الفني. عند غيابه: D9.

## 11. تعريف «منجَز» (Definition of Done)

مهمة لا تُعدّ منجزة إلا باكتمال **كل** ما يلي:

```
□ الشيفرة مكتوبة وفق 03-معايير-الكود
□ الاختبارات مكتوبة وخضراء
□ البوابات الست تمرّ في CI
□ الميزانيات محترمة (04)
□ الوصول محترم (a11y = 0 خرق حرج)
□ السيو محترم (07)
□ راجعه مطوّر آخر ووافق
□ معاينة Vercel مجرَّبة على الجوال
□ دُمج في main ونُشر
□ تُحقّق منه على الإنتاج الحيّ
□ حُذف الفرع
□ حُدّث ما يلزم من توثيق
```
